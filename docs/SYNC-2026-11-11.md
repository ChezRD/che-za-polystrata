Two upstreams were merged into the fork on 2026-11-11: PolyStrata `v0.1.45-poly.9` first, Strata
`v0.2.13.1` second. Only the engine moved. This page records the snapshots, the conflicts, the
dependencies that had to be added, the gates and what remains untested, so the next sync can repeat
or audit the work.

## Why PolyStrata first

PolyStrata's base `4de79331` is an ancestor of `main`, so its merge asked only what poly.9 changed
since that base: 17 files, two of them overlapping local edits. Strata 0.2.13 replaced the build
layout and changed CUDA defaults; doing it second kept every build or token regression attributable
to one merge. If the Strata merge had failed, `git reset --hard sync-poly-ok` would have dropped only
that merge and kept the PolyStrata work.

## What "engine only" means here

The snapshots carry `src/`, `include/`, `metal/`, `sycl/`, `cmake/`, `tests/`, `CMakeLists.txt` and
`third_party/ggml` (plus `third_party/strata-ggml` for 0.2.13). Docs, bench, serve, setup, the app and
the terminal stay out. After both merges:

```bash
git diff --stat sync-poly-ok..HEAD -- docs bench serve setup.py README*   # empty
git diff --stat sync-poly-ok..HEAD -- src/poly src/kernels/cuda/native_mmvq.cu src/kernels/local_hooks_test.cpp
# empty: the PolyStrata checkpoint is untouched by the Strata merge
```

The 17 PolyStrata files are the exception to the "engine unit" list: they are the `strata-poly`
engine and its kernels, which PolyStrata upstream maintains, and they merge from the same snapshot
model.

## PolyStrata `v0.1.45-poly.9`

The snapshot `015a9b978` is engine-only; the tag itself was not merged, so its docs and AMD bench
results did not arrive. Two files conflicted.

### `src/kernels/cuda/native_mmvq.cu`

The union keeps `main`'s IQ1_S work and adds poly.9's NVFP4 type 40:

| place | kept from `main` | added from poly.9 |
| --- | --- | --- |
| `native_mmvq_supported()` | type 19 | `ggml_type == 40` |
| `native_mmvq_weight_bytes()` | type 19 in the IQ row-bytes group | `case 40: block_elems = 64; block_bytes = 36` |
| `native_mmvq()` | `case 19` → `iq_mmvq` | `case 7: case 40:` → `iq_mmvq` |
| `slots_kind()` | type 19 in kind 2 | type 40 in kind 2 |
| `launch_slots_of()` | shape validation | 40 and 42 use 64-value blocks |

`local_hooks_test` now checks the three public facts of that wiring: `native_mmvq_supported(40)`,
`iq_row_bytes(40, 64) == 36`, and `native_mmvq_ids_supported(40)`. The file's purpose is to fail the
sync that loses a hook.

### `src/poly/qwen35.cpp`

poly.9 groups a token and its guess, or a window of two rows, into one convolution/attention call.
`main` has the k8v4 value path in the same loop. The resolution is a hand-written union, not a side:

- loop `for (int i = 0, m; i < n; i += m)` with `m = 2` when the next row has the same sequence;
- `head_norm_rope(..., 0, m, ...)`, `store_q8_at(..., m, 0, st_)`, `store_q4_at(..., m, 0, st_)`,
  `store_f16_at(..., m, 0, st_)`, `room(m)`, `fdec_*(..., m ...)`, `attend(..., m ...)`;
- the k8v4 branch still rotates `m * n_kv_` V rows with `fwht_rows`, and the post-loop
  `fwht_rows(att_, att_, n * n_head_, head_dim_, st_)` stays as it was.

`Qwen35::gdn()` auto-merged with the same `m` loop; `qwen35.hpp` gained `rows_snaps() { return true; }`.

### CMake port

`cmake/strata_poly.cmake` defines one macro, `strata_poly_targets()`, with all 35 fork targets:
`strata-poly`, `strata_poly_mmq`, `strata_poly_mmq_mxfp4`, `strata_gdn_mma`, `local_hooks_test`, the
two conversation tests and the 28 poly unit/parity tests. Mappings from the old monolith:

- `${strata_llamacpp_SOURCE_DIR}` → `${_strata_ggml_root}` (the vendored tree or `-DSTRATA_GGML_DIR`);
- `${_strata_gg}` → `${_strata_ggml_root}/ggml`; `${_strata_mmq}` fallback → `${_strata_gg}/src/ggml-cuda`;
- the 20 MMQ instances come from `third_party/poly-mmq-instances`, not from the ggml tree;
- `strata_poly_mmq` also gets `third_party/poly-ggml-headers` after `${_strata_mmq}`, so the vendored
  `common.cuh` still wins;
- `local_hooks_test` is guarded by `STRATA_ENABLE_CUDA OR STRATA_ENABLE_HIP` exactly as
  `main:CMakeLists.txt:472/1505`; gating it on `STRATA_BUILD_TESTS` would have dropped it from the
  fork's normal tests-off build.

Two upstream targets reference bench sources the engine-only snapshot does not carry:
`bench/gdn_chunk_bench.cpp` and `bench/micro/fusions_parity.cu`. `cmake/strata_gpu_engine.cmake` now
adds `AND EXISTS ...` to each guard; without it `-DSTRATA_BUILD_TESTS=ON` cannot configure. The
`gdn_chunk_parity` test, which shares the original block, was split out so it survives.

## Not tested

- Metal: not configured, built or run. No macOS here. The merged Metal files are hand-merged
  code; `STRATA_METAL_POLY` stays OFF. The proposed macOS job is manual-only and has not run.
- HIP: not configured; no ROCm toolchain. SYCL: compiled in the `strata-sycl-dev` container
  (137/137 linked), no Intel GPU for a run. Metal, HIP and SYCL commands are in
  [PLATFORM_GATES.md](PLATFORM_GATES.md).
- NVFP4 W4A8 prompt numerics: closed here with a synthetic `experts.bin` (0.516–0.546% vs
  FP64). Prompt-product speed on Ada is measured in [NVFP4.md](NVFP4.md): IQ3_S/IQ4_NL are 10–12%
  faster than W4A8 at 8K/32K, and FP16 is 22% slower than W4A8. A real NVFP4 pack and model were not
  run, so end-to-end tokens, speed and quality on Ada remain unmeasured.
- W4A4 on sm_89: not applicable and not executed.
- `ncu` counters: the normal user is blocked by `RmProfilingAdminOnly: 1`; passwordless `sudo -n ncu`
  works and profiled the decode down kernel (284.45 us, DRAM 86.64%, occupancy 61.90%). `nsys` remains
  the no-root fallback and gives per-kernel time, grid, copies and API sums; it cannot replace SM/DRAM
  utilization, occupancy or stalls. The commands are in [PLATFORM_GATES.md](PLATFORM_GATES.md).
- REAP 256K: not run in this sync. The short gate used `--max-context 4096`; the 256K numbers in
  `docs/REAP.md` are from the pre-sync tree and were not re-measured.
- Flint 4K/16K prefill ratios: not measured; only the 20K decode gate.
- `tests/terminal` and `tests/snapshot`: still need `strata_control`, which this repo does not carry.
